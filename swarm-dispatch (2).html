ศัพท์ OptaPlanner ที่ใช้ในเกมนี้
  • Planning entity = งาน (Task) ที่ solver ต้องจัดการ
  • Planning variable = งานนี้ไปอยู่เส้นทางของเอเจนต์คนไหน และลำดับที่เท่าไร (chained variable)
  • Hard constraint = กฎที่ห้ามผิด: ห้ามบรรทุกเกินความจุ, งานหนักต้องใช้เอเจนต์สายหนัก, ทุกงานต้องมีผู้รับ
  • Soft constraint = ยิ่งดียิ่งคะแนนสูง: ระยะทางรวมสั้น, งานทั้งหมดเสร็จเร็ว, ส่งไม่เกินเวลา (งานสำคัญถ่วงน้ำหนักมากกว่า)
  • Construction heuristic = สร้างคำตอบแรกด้วยการแทรกงานทีละชิ้นในตำแหน่งที่ดีที่สุด
  • Local search = ปรับแผนด้วย move (change, swap, 2-opt, tail swap) แล้วตัดสินว่ารับหรือไม่ตามอัลกอริทึม

หมายเหตุ: เป็นการ implement แนวคิดของ OptaPlanner ใหม่ในเบราว์เซอร์ ไม่ได้ใช้ไลบรารี Java ตัวจริง

📘 OptaPlanner Documentation — ส่วนที่เป็น OptaPlanner ในเกมนี้

OptaPlanner คือ constraint solver แบบ open source สำหรับ Java (ปัจจุบันพัฒนาต่อในชื่อ Timefold Solver) ใช้แก้ปัญหา planning/scheduling เช่น จัดเส้นทางรถ จัดตารางเวร จัดตารางสอน เกมนี้ใช้มันเป็นโมเดลของ “สมองวางแผน” ที่แจกงานให้หุ่นยนต์ก่อนที่ RVO จะพาหุ่นยนต์เดินจริง

ความตรงไปตรงมา: เกมนี้รันในเบราว์เซอร์ จึงไม่ได้ใช้ไลบรารี Java ของ OptaPlanner จริง แต่เขียน solver ใหม่ใน JavaScript โดยคงแนวคิด โครงสร้าง และศัพท์ให้ตรงกัน หน้านี้แสดงว่าแต่ละส่วนในเกมตรงกับอะไรใน OptaPlanner จริง และโค้ดที่แสดงด้านล่างบางส่วนดึงมาจากโค้ดที่กำลังรันอยู่จริงในหน้านี้

1. ภาพรวม: OptaPlanner ทำงานเป็นขั้นตอนอย่างไร

→

→
③ Construction Heuristicสร้างคำตอบแรกอย่างรวดเร็ว (First Fit Decreasing)

ตลอดทุกขั้นตอน Score เป็นตัวตัดสินว่าแผนไหนดีกว่า: HardSoftScore = hard (ต้อง 0 จึงใช้งานได้จริง) และ soft (ยิ่งสูง/ใกล้ 0 ยิ่งดี) การเทียบจะดู hard ก่อนเสมอ แล้วค่อยดู soft ในเกมนี้เก็บเป็นตัวเลขเดียว hard×800 + soft เพื่อเปรียบเทียบ (ดู HARD_W)

3. Domain model — โค้ด Java ที่เทียบเท่า

นี่คือหน้าตาของโมเดลเดียวกันถ้าเขียนด้วย OptaPlanner จริง (ตามรูปแบบตัวอย่าง Vehicle Routing ของ OptaPlanner ที่ใช้ chained variable)

// ตัวเชื่อมของ chain: ทั้ง Agent และ Task ต่อกันเป็นโซ่ได้
public interface Standstill {
    @InverseRelationShadowVariable(sourceVariableName = "previousStandstill")
    Task getNextTask();            // shadow variable: งานถัดไปในโซ่
    void setNextTask(Task next);
}

// Problem fact + "anchor" ของโซ่ = หุ่นยนต์ 1 ตัว
public class Agent implements Standstill {
    int capacity;   double speed;   boolean heavy;
}

@PlanningEntity                     // = งาน: สิ่งที่ solver ต้องตัดสินใจ
public class Task implements Standstill {
    int weight;  boolean heavy;  int priority;  double deadline;

    @PlanningVariable(valueRangeProviderRefs = {"agentRange", "taskRange"},
                      graphType = PlanningVariableGraphType.CHAINED)
    Standstill previousStandstill;  // "ต่อจากใคร" (เอเจนต์ หรือ งานก่อนหน้า)

    @AnchorShadowVariable(sourceVariableName = "previousStandstill")
    Agent agent;                    // shadow variable: อยู่โซ่ของเอเจนต์ไหน

    @PlanningPin boolean pinned;    // = ฟีเจอร์ล็อกงาน
}

@PlanningSolution
public class DispatchSolution {
    @ProblemFactCollectionProperty @ValueRangeProvider(id = "agentRange")
    List<Agent> agents;
    @PlanningEntityCollectionProperty @ValueRangeProvider(id = "taskRange")
    List<Task> tasks;
    @PlanningScore HardSoftScore score;
}

ตัวอย่างเพื่ออธิบายแนวคิด ไม่ได้ถูก compile หรือรันในเกมนี้ (ชื่อ annotation อาจต่างเล็กน้อยตามเวอร์ชัน OptaPlanner / Timefold)

4. Constraints — เทียบ Constraint Streams กับโค้ดที่รันจริง

Java: ConstraintProvider (เทียบเท่า) 
public class DispatchConstraints implements ConstraintProvider {
  public Constraint[] defineConstraints(ConstraintFactory f) {
    return new Constraint[]{ capacity(f), skill(f),
                             distance(f), lateness(f), makespan(f) };
  }
  // HARD: บรรทุกเกินความจุ
  Constraint capacity(ConstraintFactory f) {
    return f.forEach(Task.class)
      .groupBy(Task::getAgent, sum(Task::getWeight))
      .filter((a, load) -> load > a.getCapacity())
      .penalize(HardSoftScore.ONE_HARD,
                (a, load) -> load - a.getCapacity())
      .asConstraint("Agent capacity");
  }
  // HARD: งานหนักต้องใช้เอเจนต์สายหนัก (โทษ 5/งาน)
  Constraint skill(ConstraintFactory f) {
    return f.forEach(Task.class)
      .filter(t -> t.isHeavy() && !t.getAgent().isHeavy())
      .penalize(HardSoftScore.ofHard(5))
      .asConstraint("Heavy task needs heavy agent");
  }
  // SOFT: ระยะทางรวม
  Constraint distance(ConstraintFactory f) {
    return f.forEach(Task.class)
      .penalize(HardSoftScore.ONE_SOFT, Task::distanceFromPrevious)
      .asConstraint("Total distance");
  }
  // SOFT: ส่งช้า ถ่วงน้ำหนักด้วย priority (×40)
  Constraint lateness(ConstraintFactory f) {
    return f.forEach(Task.class)
      .filter(t -> t.lateSeconds() > 0)
      .penalize(HardSoftScore.ONE_SOFT,
        t -> (int) Math.round(40 * t.getPriority() * t.lateSeconds()))
      .asConstraint("Late delivery");
  }
  // SOFT: งานสุดท้ายเสร็จเร็ว (×120) ใช้ max เวลากลับถึงฐาน
  Constraint makespan(ConstraintFactory f) { /* groupBy(max(...)) */ }
}

📚 RVO Library Documentation

    
ไลบรารี RVO.Simulator ที่เกมนี้ใช้จริง เป็นการ implement ใหม่ด้วย JavaScript ของวิธี Reciprocal Velocity Obstacles (van den Berg, Lin & Manocha, 2008) แบบ sampling โดยตั้งชื่อ API ให้คล้าย RVO2 Library (C++) ตัวต้นฉบับ แต่ไม่ใช่ RVO2 ตัวจริง และไม่ได้ใช้ ORCA / linear programming


    
1. แนวคิด

    
เอเจนต์แต่ละตัวมี preferred velocity (ความเร็วที่อยากไปถึงเป้าหมาย) ไลบรารีจะเลือก velocity ใหม่ ที่ใกล้ preferred มากที่สุดและไม่ชนใน timeHorizon วินาที โดยสมมติว่าเพื่อนบ้านจะหลบด้วยครึ่งหนึ่ง (reciprocal) ทำให้เอเจนต์หลายตัวหลบกันได้โดยไม่ต้องสื่อสารและไม่แกว่งซ้ายขวา

    
    
      
  1. หาเพื่อนบ้านใกล้สุดไม่เกิน maxNeighbors ตัว ภายในรัศมี neighborDist
    2. 
      
  2. สุ่มตัวอย่าง velocity: preferred, หยุดนิ่ง, มุมรอบ preferred และวงแหวนรอบตัว
    3. 
      
  3. แต่ละ velocity v′ คำนวณเวลาชนกับเพื่อนบ้านด้วย v_rel = 2·v′ − vA − vB (จุด apex ของ RVO) และเวลาชนสิ่งกีดขวางสี่เหลี่ยม
    4. 
      
  4. Penalty = |v′ − v_pref| + avoidanceWeight / timeToCollision
    5. 
      
  5. เลือก v′ ที่ penalty ต่ำสุด แล้วจำกัดการเร่งด้วย maxAccel
    6.

sim.addObstacle(110, 110, 150, 40);        // x, y, width, height (สี่เหลี่ยมแนวแกน)

const b = sim.addAgent(300, 580);

for (let i = 0; i < 600; i++) {
  sim.setAgentPrefVelocity(a, 0, -60);      // อยากไปทางขึ้น 60 px/s
  sim.setAgentPrefVelocity(b, -40, -40);
  sim.doStep();
}
console.log(sim.getAgentPosition(a));       // { x, y }

    •
